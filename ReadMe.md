# Database Query Performance Profiler

## Complete Requirements Table

| Req ID | Type | Description | Priority | Acceptance Criteria | Rationale | Comments |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **FR-001** | Functional | The system shall parse Postgres/MySQL EXPLAIN plans, highlight sequential table scans on large tables, and recommend optimal index column definitions. | High | **Pass:** Missing composite index identified on filtered columns; **Fail:** Query plan with sequential scan marked optimized. | Identifies performance bottlenecks and suggests corrective indexes. | Provided baseline requirement. |
| **FR-002** | Functional | The system shall ingest slow query logs continuously from target database instances. | High | **Pass:** Logs captured and parsed within 5 seconds of creation; **Fail:** Log entries dropped or unparsed after threshold. | Essential for collecting raw performance data needed for analysis. | Core input feature. |
| **FR-003** | Functional | The system shall generate weekly performance optimization digests summarizing slow query trends and index recommendations. | Medium | **Pass:** Digest generated every Monday at 00:00 UTC with top 10 slowest queries; **Fail:** Digest fails to render or omits metrics. | Provides actionable executive summaries for database health tracking. | Scheduled reporting feature. |
| **FR-004** | Functional | The system shall allow Database Administrators to set custom execution time thresholds for filtering slow queries. | Medium | **Pass:** Queries executing under the set threshold (e.g., <200ms) are excluded; **Fail:** Queries below threshold appear in slow logs. | Prevents logging noise and allows focus on critical latency issues. | Custom configuration support. |
| **FR-005** | Functional | The system shall trigger real-time alert notifications to the Backend Lead when a query execution exceeds a critical latency limit. | High | **Pass:** Alert dispatched to configured channel within 30 seconds of query execution; **Fail:** Alert delayed or not sent. | Enables rapid response to severe query performance regressions. | Escalation mechanism. |
| **NFR-001** | Non-Functional | Slow query log ingestion must handle up to 5,000 log records per minute without dropping entries or slowing host DB. | High | **Pass:** Benchmarking tests confirm target latency and security standards under simulated peak load; **Fail:** System drops logs or host DB latency increases during peak load. | Ensures high throughput without degrading production database performance. | Provided baseline NFR. |
| **NFR-002** | Non-Functional | The system shall encrypt all ingested log data and execution plans in transit using TLS 1.3 and at rest using AES-256 encryption. | High | **Pass:** Security audit confirms valid encryption protocols on all data paths; **Fail:** Unencrypted plaintext query logs detected in storage or transmission. | Protects sensitive database schemas and query parameter values. | Security compliance standard. |
